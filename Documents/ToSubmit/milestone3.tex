\section{Application Overview}
%--------------------------------------------------------------

\textbf{WorkFlow} is a cross-platform mobile application (iOS/Android) designed for coordinating field work teams in the construction and maintenance industry. It replaces inefficient phone- or email-based communication by giving managers an instant, real-time overview of task progress and team locations.

The application allows a manager to create projects and assign tasks within them to workers based on their skill certificates. Workers receive push notifications about new assignments, can update task statuses, upload photo documentation directly from the field, and communicate with the manager via a built-in chat. The manager tracks live worker locations on a map and views worker qualifications through submitted certificates.

\subsection*{Key Features}
\begin{itemize}[noitemsep]
    \item \textbf{Project \& Task Management} --- Create, edit, delete projects and tasks with priorities and deadlines
    \item \textbf{Certificate-Based Assignment} --- Workers assigned only to tasks matching their verified qualifications
    \item \textbf{Real-Time Location Tracking} --- Live GPS map of all workers on a project
    \item \textbf{Offline Mode} --- Task status updates survive without internet; auto-sync on reconnect
    \item \textbf{Built-in Chat} --- Real-time WebSocket messaging between manager and workers
    \item \textbf{Push Notifications} --- Expo Push delivery for assignments and task completions (background + deep-link tap)
    \item \textbf{Audit Logging} --- Immutable record of all actions for accountability
    \item \textbf{Dashboard} --- Role-specific statistics overview
\end{itemize}

\subsection{Technology Choice Rationale}

React Native with Expo was chosen as the frontend framework after evaluating React Native, Flutter, and Kotlin Multiplatform:

\begin{itemize}[noitemsep]
    \item \textbf{Shared Socket.IO library} --- identical \texttt{socket.io-client} on frontend and \texttt{socket.io} on backend simplifies real-time debugging
    \item \textbf{Node.js backend synergy} --- TypeScript across the full stack reduces context-switching
    \item \textbf{Expo ecosystem} --- camera, location, notifications, and document picker available as turnkey Expo modules
    \item \textbf{Cross-platform} --- single codebase targets both iOS (15+) and Android (10+)
\end{itemize}

\section{User Roles}
%--------------------------------------------------------------

The application defines two user roles with distinct permissions.

\subsection{Manager}

The Manager has full administrative control over projects, tasks, and the team:

\begin{itemize}[noitemsep]
    \item Creates, edits, and deletes projects (title, description, GPS, deadline, client info)
    \item Creates, edits, and deletes tasks within projects (title, description, category, priority, deadline)
    \item Assigns tasks to workers based on their verified skill certificates
    \item Views live worker positions and task-site pins on the project map
    \item Has a full overview of all tasks and their current statuses with progress indicators
    \item Invites new workers to the application via a unique numeric code sent by SMS or email
    \item Communicates with workers via the built-in real-time chat
    \item Receives a push notification when a worker marks a task as \textit{Done}
    \item Views audit logs of all actions in the system
    \item Monitors dashboard statistics (project count, task breakdown, worker count)
\end{itemize}

\subsection{Worker}

The Worker has restricted access --- only to tasks and projects assigned to them:

\begin{itemize}[noitemsep]
    \item Views the list of assigned tasks within projects
    \item Opens task detail: description, category, assigned person, deadline, photos, and status
    \item Changes the task status to \textit{In Progress} or \textit{Done}
    \item Uploads photo documentation from the camera or gallery
    \item Uploads skill certificates (visible to the manager in the Workers screen)
    \item Shares GPS location with the manager (every 10 seconds via WebSocket)
    \item Communicates with the manager and other workers via chat
    \item Receives a push notification when a new task is assigned
    \item Can update task status offline; the change syncs automatically after reconnection
    \item Manages profile: name, date of birth, hourly rate, bank information, profile photo
\end{itemize}

\section{Use Cases}
%--------------------------------------------------------------

\subsection{Manager Use Cases}

\textbf{UCM1 --- Login:} The Manager logs into the application using Google SSO or email and password. Upon successful authentication a JWT token is issued and stored securely on the device.

\textbf{UCM2 --- Create, edit, delete a project:} The Manager creates a new project by filling in the project title, description, deadline, construction site address, GPS coordinates, and client information (name, phone, email). Existing projects can be edited or permanently deleted. Deleting a project removes all associated tasks and assignments.

\textbf{UCM3 --- Create, edit, delete a task:} Within a project the Manager creates tasks by specifying a title, description, category (e.g.\ Electrical, Heating), priority (Low / Medium / High), and deadline. Tasks can be edited or deleted at any time. Only workers with a verified certificate matching the task category are eligible for assignment.

\textbf{UCM4 --- Assign a task to a worker:} The Manager assigns a task to one or more workers. The assignment screen displays available workers filtered by their verified skill certificates and flags workers missing the required qualification as ineligible. Upon assignment the worker receives a push notification.

\textbf{UCM5 --- View all tasks and their statuses:} The Manager sees a full list of tasks within a project with their current statuses (Pending, In Progress, Done) and an overall progress indicator showing how many tasks have been completed.

\textbf{UCM6 --- Team map:} The Manager opens a project-specific map showing the live GPS positions of all workers assigned to that project, updated every 10 seconds via WebSocket. Workers are shown with an online/offline indicator.

\textbf{UCM7 --- Chat with a worker:} The Manager initiates or continues a real-time conversation with any worker via the built-in chat. Messages are delivered instantly over a WebSocket connection.

\textbf{UCM8 --- Invite a new worker:} The Manager generates a unique numeric registration code from the Worker List screen. The code is sent to the prospective worker via SMS or email. The worker enters the code in the registration screen to join the Manager's team.

\textbf{UCM9 --- Receive notification when a task is completed:} When a worker marks a task as Done, the Manager receives a background push notification. Tapping the notification navigates directly to the relevant task detail.

\subsection{Worker Use Cases}

\textbf{UCW1 --- Login:} The Worker logs into the application using Google SSO or email and password.

\textbf{UCW2 --- View list of assigned tasks:} The Worker sees only the projects and tasks assigned to them. Each task card shows the title, category, deadline, and current status.

\textbf{UCW3 --- Open task detail:} The Worker opens a task to view the full description, category, assigned person, deadline, priority, and any previously uploaded photos.

\textbf{UCW4 --- Update task status:} The Worker changes the task status to \textit{In Progress} or \textit{Done} directly from the task card. The change is reflected in real time on the Manager's view.

\textbf{UCW5 --- Upload a photo to a task:} The Worker attaches photo documentation to a task by taking a photo with the camera or selecting one from the gallery. Multiple photos can be uploaded per task.

\textbf{UCW6 --- Upload skill certificates:} The Worker submits a certificate of qualification for a specific skill category by uploading a photo of the document. The certificate becomes visible to the Manager in the Workers screen and determines which task categories the Worker is eligible for.

\textbf{UCW7 --- Offline task status update:} When the device has no internet connection the Worker can still change a task status. The change is saved locally with a pending sync flag and automatically synchronised with the server once connectivity is restored. Conflicts are resolved with a server-wins policy.

\textbf{UCW8 --- Chat with the manager:} The Worker sends and receives real-time messages with the Manager. If the device is offline the chat is unavailable and an informative banner is shown.

\textbf{UCW9 --- Receive notification about a new task assignment:} When the Manager assigns a task to the Worker, a background push notification is delivered to the Worker's device. Tapping the notification navigates directly to the task detail.

\section{System Architecture}
%--------------------------------------------------------------

\subsection{Architecture Overview}

The system consists of three main components:

\begin{enumerate}[noitemsep]
    \item \textbf{Mobile application (React Native + Expo)} --- cross-platform client for iOS and Android
    \item \textbf{Backend server (Node.js / Express)} --- REST API + Socket.IO WebSocket server
    \item \textbf{Database (PostgreSQL)} --- persistent relational data store
\end{enumerate}

\begin{mdframed}[backgroundcolor=lightgray, linecolor=headerblue, linewidth=1pt]
\begin{center}
\textbf{Communication Architecture}\\[0.5em]
\begin{tabular}{lcl}
Mobile App & $\longleftrightarrow$ & Backend: \textbf{HTTPS REST API} (standard CRUD operations) \\[0.3em]
Mobile App & $\longleftrightarrow$ & Backend: \textbf{WebSocket (Socket.IO)} (chat + location updates) \\[0.3em]
Backend    & $\longrightarrow$    & Mobile App: \textbf{Expo Push Notifications} (FCM/APNs abstraction) \\
\end{tabular}
\end{center}
\end{mdframed}

\subsection{Backend Architecture}

The backend follows a layered REST architecture running on \texttt{http://localhost:3000}. All protected endpoints require a Bearer JWT token in the \texttt{Authorization} header.

\begin{tabular}{lp{0.65\textwidth}}
\toprule
\textbf{Layer} & \textbf{Responsibility} \\
\midrule
\textbf{Routes} & Define HTTP method, path, and optional file-upload middleware; delegate to query handlers \\
\textbf{Queries} & Contain business logic and execute direct SQL via \texttt{pg} Pool \\
\textbf{Middleware} & JWT authentication guard applied globally (except \texttt{/api/auth} and \texttt{/api/invite}) \\
\textbf{Socket} & Socket.IO server authenticated via JWT handshake; each user joins a private room \texttt{user:\{id\}} for targeted message delivery \\
\textbf{Services} & Expo Push helper for task assignment and status-change notifications; audit log writer \\
\bottomrule
\end{tabular}

\subsection{Frontend Architecture}

The React Native (Expo) application uses a file-system based routing approach via \textbf{Expo Router}:

\begin{tabular}{lp{0.62\textwidth}}
\toprule
\textbf{Directory} & \textbf{Purpose} \\
\midrule
\texttt{app/}             & Expo Router screens (file = route) \\
\texttt{app/auth/}        & Login, registration, and sign screens \\

\texttt{api/}             & Axios HTTP client, Socket.IO client, endpoint modules per resource \\
\texttt{api/endpoints/}   & Per-resource typed API calls (projects, tasks, users, messages, etc.) \\
\bottomrule
\end{tabular}

\subsection{Real-Time Communication}

The server exposes a Socket.IO endpoint authenticated via JWT handshake. Upon connection each client joins a private room \texttt{user:\{id\}}. The REST \texttt{POST /api/messages} route saves the message to the database and then calls \texttt{emitNewMessage(receiverId, message)} to push the message instantly to the recipient's socket room without polling.

Worker location updates are sent from the mobile client every 10 seconds and broadcast to the manager's room via \texttt{emitLocationUpdate()}.

\subsection{Security}

\begin{itemize}[noitemsep]
    \item Passwords are stored as \textbf{bcrypt} hashes (v6, cost factor 12)
    \item All state-changing endpoints are protected by the JWT middleware (verified against \texttt{JWT\_SECRET})
    \item Google OAuth is handled server-side via \textbf{Passport.js}; no client secret is exposed to the frontend
    \item File uploads are handled in-memory by \textbf{Multer} and stored as binary in the database (\texttt{bytea}), avoiding unauthenticated public file URLs
    \item JWT tokens stored on the device using \textbf{expo-secure-store} (iOS Keychain / Android Keystore)
    \item Role-based access control (RBAC) enforced at the query layer --- workers cannot access manager-only endpoints
\end{itemize}

\section{Changes from Original Design}
%--------------------------------------------------------------

The following changes were made from the original specification (Milestone 1) during implementation:

\begin{tabularx}{\textwidth}{|l|X|X|}
\hline
\textbf{Area} & \textbf{Original Design} & \textbf{Implemented} \\
\hline
File storage & External cloud bucket (S3 / Cloudinary) & Binary stored directly in PostgreSQL (\texttt{bytea}); eliminates external dependency and simplifies auth \\
\hline
Task photos & Separate \texttt{task\_photos} table & \texttt{task\_id} FK added to \texttt{project\_photos}; unified photos table reduces query complexity \\
\hline
Push notifications & FCM + APNs (separate credentials) & Expo Push SDK (\texttt{expo-server-sdk}); single token per device, abstracts FCM/APNs automatically \\
\hline
Frontend state & Redux Toolkit + WatermelonDB & AsyncStorage + expo-sqlite for simpler offline sync; appropriate for current app scale \\
\hline
Offline sync & WatermelonDB reactive sync & \texttt{task\_status\_sync} table with server-wins conflict resolution; simpler and sufficient for the task-status use case \\
\hline
PVP choice & PVP5 --- Firebase Analytics + Crashlytics & \textbf{PVP2 --- Accessibility} (screen reader labels, gesture navigation, WCAG colour contrast); Firebase dependencies removed from project \\
\hline
Certificate flow & Manager manually accepts or rejects each certificate & Certificate is uploaded by the worker and immediately visible to the manager; no explicit accept/reject step --- the manager uses certificate presence to decide assignment eligibility \\
\hline
Worker invite & Unique URL invite link copied and shared & Unique multi-digit numeric code generated by the server and sent to the worker via SMS or email; worker enters the code during registration \\
\hline
Platform target & iOS 17+ and Android 10+ & \textbf{iOS 15+ and Android 10+}; Expo SDK 54 and React Native 0.81 support iOS 15 and Android API level 29 (10) as minimum targets \\
\hline
\end{tabularx}

\section{Mandatory Requirements Coverage}
%--------------------------------------------------------------

The project specification defines a set of mandatory features that every submission must contain. The table below confirms that WorkFlow implements each requirement in full.

\begin{tabularx}{\textwidth}{|p{0.32\textwidth}|X|p{0.12\textwidth}|}
\hline
\textbf{Requirement} & \textbf{Implementation in WorkFlow} & \textbf{Status} \\
\hline
\textbf{User management} --- persistent authentication; at least two roles with different permissions &
JWT token stored in \texttt{expo-secure-store} (iOS Keychain / Android Keystore); token is refreshed on every launch. Two roles: \textbf{Manager} (full control) and \textbf{Worker} (own tasks only). Role enforced both in the UI and at the API layer (403 returned for role violations). &
\checkmark\ Done \\
\hline
\textbf{Offline mode} --- create, edit, and delete a data entity without internet; change applied in the background on reconnect; conflict handling &
Workers can update task status while offline. Changes are written to the local \texttt{task\_status\_sync} table. On reconnect, \texttt{@react-native-community/netinfo} detects connectivity and the sync job flushes the queue to the server. Conflicts are resolved with a server-wins policy. &
\checkmark\ Done \\
\hline
\textbf{Real-time WebSocket communication} --- interactive, bidirectional &
Socket.IO (v4.8) is used for: (1) bidirectional chat between manager and workers; (2) live GPS location updates sent by workers every 10 s and rendered on the manager's map in real time. Each client authenticates via JWT on the Socket.IO handshake. &
\checkmark\ Done \\
\hline
\textbf{Dark mode support} &
The application respects the system colour scheme via React Native's \texttt{useColorScheme} hook. All screens, components, and navigation elements switch between light and dark themes automatically. &
\checkmark\ Done \\
\hline
\textbf{Push notifications} --- triggered by the app and by the server; at least one notification deep-links to relevant content; works while the app is in the background &
Notifications are sent by the server (Expo Push SDK) when: a task is assigned to a worker, and when a worker marks a task as Done. Both notifications carry a deep link payload; tapping them navigates directly to the relevant task detail screen. Delivery works while the app is backgrounded or closed. &
\checkmark\ Done \\
\hline
\textbf{Permission handling} --- the app requests access to system resources (gallery, camera, microphone, files, location, ...) &
The app requests permissions at the point of use via Expo APIs: \texttt{expo-image-picker} (camera + gallery), \texttt{expo-location} (foreground GPS), \texttt{expo-notifications} (push), \texttt{expo-document-picker} (certificate files). Permission denial is handled gracefully with user-facing explanations. &
\checkmark\ Done \\
\hline
\end{tabularx}
